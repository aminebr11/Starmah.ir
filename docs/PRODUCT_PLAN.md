# ستاره ماه ۲.۰ — طرح جامع محصول (نسخه پیش‌نویس v0.1)

> سندِ زنده. این نسخه‌ی اولیه برای نهایی‌سازی مشترک است؛ بعد از توافق روی تصمیم‌های کلیدی، به‌روزرسانی می‌شود.

---

## ۱) چشم‌انداز محصول (Vision)

یک پلتفرم آموزشی **گیمیفای‌شده و شخصی‌سازی‌شده بر اساس علاقه‌ی کودک**، که به‌صورت **SaaS به مدارس فروخته می‌شود** (مدل B2B2C).

جمله‌ی محوری:
> «هر دانش‌آموز دنیای آموزشی خودش را دارد — بچه‌ای که عاشق فوتبال و تیم قرمز است، ریاضی و املا را در قالب لیگ، گل و قهرمانی یاد می‌گیرد؛ بچه‌ای که عاشق ماشین است، همان مفاهیم را در قالب مسابقه و گرنپری.»

سه ستون ارزش:
1. **شخصی‌سازی بر پایه‌ی علاقه (Interest-Driven Learning):** تم، روایت، شخصیت، و حتی متن سؤال‌ها بر اساس علاقه‌ی دانش‌آموز عوض می‌شود.
2. **مسیر یادگیری + رقابت سالم:** هر دانش‌آموز مسیر تطبیقی (adaptive) خودش را دارد؛ همراه با رقابت کلاسی/مدرسه‌ای تیمی و فردی.
3. **ابزار قدرتمند برای معلم و مدرسه:** معلم کلاس می‌سازد، تکلیف/آزمون می‌دهد، پیشرفت را می‌بیند؛ مدیر مدرسه گزارش کلان دارد.

## ۲) کاربران و نقش‌ها (Personas & Roles)

| نقش | کیست | کارهای اصلی |
|---|---|---|
| **Super Admin** | تو (مالک پلتفرم) | مدیریت مدارس، اشتراک‌ها، تم‌ها، بانک محتوا، صورت‌حساب |
| **School Admin** | مدیر/معاون مدرسه | ساخت کلاس‌ها، افزودن معلم‌ها و دانش‌آموزها، گزارش کلان مدرسه، تمدید اشتراک |
| **Teacher** | معلم | ساخت کلاس، اختصاص تکلیف/آزمون، دیدن پیشرفت، تشویق/پاداش |
| **Student** | دانش‌آموز | انتخاب تم/علاقه، بازی و تمرین، آزمون، پیشرفت در مسیر، رقابت |
| **Parent** (فاز ۲) | والدین | دیدن پیشرفت و تکالیف فرزند، تشویق |

سلسله‌مراتب داده: `Platform → School (tenant) → Class → (Teacher, Student)` و `Parent ↔ Student`.

## ۳) معماری فنی (Tech Architecture)

### محدودیت کلیدی: هاست cPanel
cPanel یعنی PHP 8.3 + MySQL/MariaDB روی Apache/LiteSpeed، بدون Docker و بدون اجرای پایدار Node.js. طراحی باید این را محترم بشمارد. بنابراین:

### استک پیشنهادی (مدرن ولی سازگار با cPanel)
- **بک‌اند:** **Laravel 11** (PHP 8.3) — استاندارد مدرن PHP، روی cPanel بومی اجرا می‌شود.
- **رابط کاربری دانش‌آموز:** **React + Inertia.js + Tailwind CSS**، خروجی **PWA** (نصب‌شدنی روی موبایل و دسکتاپ، آفلاین نسبی). Inertia یعنی بدون نیاز به API جدا، تجربه‌ی SPA غنی با سادگی Laravel و دیپلوی تک‌مرحله‌ای.
- **پنل‌های مدیریتی (معلم/مدرسه/سوپرادمین):** **Filament** (پنل ادمین Laravel) — ساخت داشبوردهای پرامکانات با سرعت چند برابر.
- **دیتابیس:** MySQL موجود؛ بازطراحی schema با Migrationها.
- **احراز هویت:** Laravel Sanctum + نقش‌ها (Spatie Permission). ورود با **شماره موبایل + کد پیامکی** (مرسوم در ایران) از طریق سرویس پیامک ایرانی (کاوه‌نگار/...).
- **Real-time** (تخته/چت/لیدربورد زنده): چون cPanel وب‌سوکت پایدار ندارد → سرویس مدیریت‌شده (Pusher/Ably/Soketi میزبانی‌شده) با Laravel Echo.
- **کلاس آنلاین ویدیویی:** سرویس بیرونی (LiveKit Cloud / Daily / Jitsi-as-a-service) — هرگز روی cPanel میزبانی نشود.
- **هوش مصنوعی:** صف‌های Laravel (Queue + Cron) که Claude/OpenAI را صدا می‌زنند و خروجی را **کش/ذخیره** می‌کنند (نه در لحظه‌ی هر درخواست).
- **پرداخت:** درگاه‌های ایرانی (زرین‌پال/IDPay/نکست‌پی) — Stripe در ایران کار نمی‌کند.

### مسیر مقیاس‌پذیری (آینده)
شروع روی cPanel برای MVP. وقتی کاربر زیاد شد، فقط **بک‌اند** را به یک VPS ارزان/PaaS (مثلاً با Laravel Forge) منتقل می‌کنیم؛ فرانت‌اند چون static build است هرجا اجرا می‌شود.

### چندمستأجری (Multi-Tenancy)
مدل **single-database + ستون `school_id`** روی جداول مرتبط (ساده، ارزان، سازگار با MySQL اشتراکی). جداسازی داده در سطح اپلیکیشن با Global Scope. (دیتابیس-به‌ازای-هر-مدرسه روی هاست اشتراکی پرهزینه و غیرضروری است.)

## ۴) مدل دامنه و داده (Domain Model)

محتوا از تم جداست — این کلید مقیاس‌پذیری تم‌هاست.

- **Curriculum (محتوای خنثی):** `Subject → Unit/Topic → Skill → Activity/Question`
  بانک سؤال «خنثی نسبت به تم» است (مثلاً مهارت: «جمع دو رقمی»).
- **Theme/World (تم):** بسته‌ی شخصی‌سازی (فوتبال، ماشین، فضا، حیوانات، ...).
- **Student Profile:** تم انتخابی، آواتار، علاقه‌ها، پایه‌ی تحصیلی.
- **Progress:** mastery هر مهارت، XP، streak، نشان‌ها.
- **Gamification:** XP، سطح/لیگ، نشان، لیدربورد، کوئست/مأموریت، فروشگاه آواتار (کازمتیک).
- **Assignments:** تکلیف، کوییز، آزمون (اختصاص توسط معلم).
- **Analytics:** داشبورد معلم/مدرسه/والد.

## ۵) ⭐ موتور تم و شخصی‌سازی (تمایز اصلی محصول)

سه لایه — از ارزان/فوری تا عمیق/هوشمند:

### لایه ۱ — پوسته‌ی بصری (Skin) | ارزان، بی‌نهایت مقیاس‌پذیر
تم = یک «بسته‌ی توکن طراحی»: رنگ‌ها، فونت، شخصیت/ماسکوت، پس‌زمینه، صداها، آیکون‌ها، انیمیشن‌ها.
پیاده‌سازی با CSS variables / تم Tailwind + بسته‌ی asset. تعویض تم = تعویض بسته‌ی توکن. **هیچ تغییری در محتوا لازم نیست.**

### لایه ۲ — روایت و واژگان گیمیفیکیشن (Narrative)
نگاشت مفاهیم عمومی بازی به واژگان تم (یک فایل JSON برای هر تم):
- امتیاز → «گل» (فوتبال) / «نیترو» (ماشین)
- سطح → «لیگ‌ها: برنز تا قهرمانان» / «مراحل گرنپری»
- نام نشان‌ها، انیمیشن ارتقا، واکنش ماسکوت، پیام‌های تشویقی.

### لایه ۳ — محتوای تم‌دار (Themed Content) | عمیق، با کمک AI
همان مهارت آموزشی، اما «روکش داستانی» بر اساس تم:
- **استراتژی الف — قالب با متغیر (Template slots):** سؤال‌ها جای‌خالی دارند؛ تم لیست اسم‌ها را می‌دهد (بازیکن‌ها، تیم‌ها، ماشین‌ها). ارزان، قطعی، بدون هزینه‌ی AI در لحظه.
- **استراتژی ب — تولید با AI:** ساخت دسته‌ای نسخه‌های تم‌دار به‌صورت آفلاین (Queue)، بازبینی کیفی، و **کش** کردن. از همان کلیدهای Claude/OpenAI موجود استفاده می‌کند.
- **پیشنهاد: ترکیبی** — بیشتر سؤال‌ها با قالب؛ متن‌های خواندنی/مسئله‌های کلامی با AI تولید، بازبینی و کش شوند.

نتیجه: افزودن یک تم جدید (مثلاً «دایناسورها») = یک بسته‌ی Skin + یک JSON روایت + چند لیست اسم. بدون بازنویسی محتوای آموزشی.

## ۶) مسیر یادگیری تطبیقی (Adaptive Learning Path)
- هر دانش‌آموز یک «گراف مهارت» با نمره‌ی mastery دارد.
- موتور انتخاب فعالیت بعدی: ابتدا **قاعده‌محور** (تمرین ضعیف‌ترین مهارت‌ها + مرور فاصله‌دار/spaced repetition + تنظیم سختی) → بعداً ML.
- **کوئست/مأموریت:** اهداف روزانه/هفتگی تم‌دار که دانش‌آموز را در مسیر برنامه‌ی درسی هدایت می‌کنند.

---

## ۷) رقابت و انگیزش (با طراحی آموزشی سالم)
- **لیدربورد:** کلاس، مدرسه، (اختیاری: فصلی بین‌مدرسه‌ای) — در قالب جدول لیگ تم‌دار.
- **فصل‌ها (Seasons):** ریست هفتگی/ماهانه برای حفظ انگیزه («فصل لیگ»).
- **بازی تیمی:** تقسیم کلاس به تیم‌های تم‌دار، اهداف مشارکتی.
- **ضدفشار:** مسیر «رکورد شخصی» در کنار رقابت، تا دانش‌آموز ضعیف‌تر دلسرد نشود — مهم برای فروش به مدرسه و توجیه آموزشی.

## ۸) مدل تجاری‌سازی (Monetization — B2B به مدارس)
- **اشتراک سالانه‌ی هر مدرسه**، پلکانی بر اساس تعداد دانش‌آموز (مدارس سالانه بودجه‌ریزی می‌کنند).
- **پلن‌ها:**
  - *Basic:* تمرین گیمیفای‌شده‌ی پایه + لیدربورد کلاسی.
  - *Pro:* + محتوای تم‌دار AI + آزمون‌ساز + تحلیل پیشرفت.
  - *Premium:* + کلاس آنلاین + پنل والدین + برندینگ اختصاصی مدرسه (white-label).
- **افزونه‌ها:** تم‌های ویژه، برندینگ سفارشی.
- **تریال رایگان:** ۱ کلاس / ۳۰ روز — برای جذب پایین‌به‌بالا توسط معلم.
- **پرداخت:** درگاه ایرانی + صورت‌حساب سالانه از پنل سوپرادمین.

## ۱۰) چه چیزی از کد فعلی نگه می‌داریم؟
رویکرد: **بازطراحی greenfield** (Laravel + React) چون خودت «بازطراحی» خواستی و `index.php` ۱۴۷ کیلوبایتی قابل refactor تدریجی به‌صرفه نیست. اما این‌ها را **حفظ/منتقل** می‌کنیم:
- منطق XP و سطح‌بندی و آزمون‌ساز (ارزشمند).
- یکپارچگی موجود با Claude/OpenAI برای تولید سؤال.
- توابع تاریخ جلالی.
- درک دامنه از روی schema فعلی (۷۰ جدول → بازطراحی به ~۲۵ جدول تمیز).
- مهاجرت داده‌ی واقعی (کم است، آسان).

جداول تکراری حذف می‌شوند (`games`/`games1`، `quizzes`/`quizzes_backup`، سه ست کلاس آنلاین → یکی).

## ۱۱) نقشه‌ی راه فازبندی‌شده (Roadmap)

**فاز ۰ — پایه و امنیت**
باطل/انتقال اسرار به `.env`، حذف فایل‌های دیباگ، راه‌اندازی اسکلت Laravel + React/Inertia + Filament، schema تمیز + احراز هویت نقش‌محور + پایه‌ی multi-tenant.

**فاز ۱ — MVP قابل فروش**
یک درس (مثلاً ریاضی) + ۲–۳ تم (لایه Skin + Narrative + محتوای قالبی)، حلقه‌ی تمرین دانش‌آموز، XP/سطح/نشان، لیدربورد کلاسی، داشبورد معلم (ساخت کلاس، اختصاص، دیدن پیشرفت)، پنل مدرسه. PWA. ورود پیامکی + یک درگاه پرداخت + قفل اشتراک.

**فاز ۲ — تمایز و عمق**
لایه‌ی محتوای AI، آزمون/کوییز‌ساز (پورت از کد فعلی)، تم‌ها/درس‌های بیشتر، پنل والدین، تحلیل پیشرفته.

**فاز ۳ — مقیاس**
کلاس آنلاین، موتور تطبیقی پیشرفته، white-label، بازارچه‌ی تم، در صورت نیاز رپر موبایل نیتیو (Capacitor).

## ۱۲) تصمیم‌های نهایی‌شده ✅
1. **استک:** Laravel 11 + React/Inertia + Tailwind (PWA) + Filament. (تأییدشده)
2. **درس/پایه‌ی MVP:** ریاضی چهارم.
3. **تم‌ها:** معماری باید **افزودن آسان تم در آینده** را پشتیبانی کند (موتور سه‌لایه). برای شروع فقط **تم ۱: فوتبال** و **تم ۲: ماشین/مسابقه** ساخته می‌شوند؛ بقیه بعداً به‌صورت بسته اضافه می‌شوند.
4. **بازار هدف:** همه‌ی بخش‌ها (غیرانتفاعی، دولتی، آموزشگاه/کلاس خصوصی). طراحی باید انعطاف داشته باشد: پلن‌بندی پلکانی + امکان مدرسه‌ی کوچک تا بزرگ. شروع فروش از جایی که سریع‌ترین تصمیم گرفته می‌شود (غیرانتفاعی/آموزشگاه) منطقی است، اما محصول همه را پوشش می‌دهد.

## ۱۳) فاز ۰ (پایه‌گذاری) — ✅ انجام شد
1. ✅ **سازماندهی و امنیت ریپو:** کد نسخه‌ی ۱ به `legacy/` منتقل شد؛ اسرار به `.env` (gitignore) رفتند؛ `.env.example` با همه‌ی بخش‌ها (MySQL/cPanel، AI، پیامک، پرداخت).
2. ✅ **اسکلت پروژه:** Laravel 13 + Breeze/Inertia + React + Tailwind + Sanctum + Spatie Permission (Filament در فاز بعد).
3. ✅ **schema تمیز نسخه‌ی ۲:** ~۲۱ جدول تمیز (به‌جای ۷۰ جدول قدیمی) — کاربر/نقش، school/tenant، class/season، subject→topic→skill→question، theme، assignment، xp/mastery/badge، discipline، parent/messages.
4. ✅ **چندمستأجری:** trait `BelongsToSchool` + Global Scope + seeder مدرسه‌ی نمونه.
5. ✅ **احراز هویت نقش‌محور:** ورود با موبایل یا ایمیل + پنج نقش. (OTP پیامکی واقعی = قدم بعدی)
6. ✅ **موتور تم:** سرویس `ThemeEngine` با سه لایه (Skin/Narrative/Content)؛ دو تم فوتبال و ماشین seed شد؛ داشبورد دانش‌آموز کاملاً تم‌دار و **اثبات‌شده‌ی end-to-end** (ورود واقعی → رندر متفاوت بر اساس تم کاربر).

### قدم بعدی (شروع فاز ۱)
- پنل‌های مدیریتی با **Filament** (معلم/مدرسه/سوپرادمین).
- جریان واقعی **OTP پیامکی** (درایور کاوه‌نگار).
- بقیه‌ی صفحات دانش‌آموز (مسابقه، جدول، کارنامه، پل والدین) به‌صورت صفحات Inertia کامل.
- حلقه‌ی تمرین + ثبت XP/mastery + اختصاص تکلیف توسط معلم.
